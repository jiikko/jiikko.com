Connect Google Cloud Storage to Obaket

Last updated: November 26, 2026

Coming soon. Google Cloud Storage support is still being tested and is not yet in the version of Obaket on the Mac App Store. This page describes how it will work once it is available.

Obaket is a macOS file manager for cloud storage. After you connect a Google Cloud Storage bucket, you can browse its files and folders, preview them with thumbnails, upload and download files, and rename, move, copy, and delete items, next to your other cloud storage in one window.

Obaket connects to one bucket with an HMAC key (an Access key and a Secret). This page shows how to create a bucket, a service account, and an HMAC key in the Google Cloud console, and then how to enter them in Obaket. If you already have a bucket and an HMAC key, skip to Connect in Obaket.

Before you start

  • A Mac running macOS 15 or later with a version of Obaket from the Mac App Store that lists Google Cloud Storage under Add Connection.
  • A Google Cloud project where you can use Cloud Storage. Google Cloud may ask you to set up billing for the project.
  • Permission in that project to create buckets, service accounts, and HMAC keys. The project owner has all of these. Otherwise ask for the roles Storage Admin, Create Service Accounts, and Storage HMAC Key Admin.

Step 1. Create a bucket

Skip this step if you want to use a bucket you already have.

  1. In the Google Cloud console, open Cloud Storage › Buckets and click Create.
  2. Enter a bucket name. The name must be unique across all of Google Cloud. Use 3 to 63 lowercase letters, digits, hyphens (-), underscores (_), and dots (.), and start and end with a letter or digit (names with dots can be longer). See Bucket names for all the rules.
  3. The other settings (location, storage class, access control, data protection) can stay as they are. Click Create.

Google describes the settings in Create buckets.

Step 2. Create a service account

A service account is an account for an app rather than a person. Obaket acts with the permissions of this account, so you can limit Obaket to one bucket.

  1. Open IAM & Admin › Service accounts › Create service account and select your project.
  2. Enter a name, for example obaket.
  3. Click Done. You do not need to give the account roles on the whole project here; Step 3 gives it access to the bucket only.

See Create service accounts.

Step 3. Give the service account access to the bucket

  1. On the Buckets page, click the name of your bucket.
  2. Open the Permissions tab and click Grant access.
  3. In New principals, enter the email address of the service account from Step 2 (it ends with .iam.gserviceaccount.com).
  4. In Select a role, choose Cloud Storage › Storage Object User, then click Save.

Storage Object User lets the account list, read, create, replace, and delete objects and multipart uploads. Obaket does not need Storage Object Admin, which adds changing access and retention settings. See Use IAM permissions and IAM roles for Cloud Storage.

Step 4. Create an HMAC key

  1. Open Cloud Storage › Settings and select the Interoperability tab.
  2. Under Access keys for service accounts, click Create a key for a service account.
  3. Select the service account from Step 2 and click Create key.
  4. Copy the Access key (it starts with GOOG1) and the Secret. Google Cloud shows the secret only when you create the key; if you lose it, create a new key.

A new key can take up to a minute before it works. See Manage HMAC keys for service accounts.

Use the HMAC key, not a JSON key file. The JSON key file of a service account (“Keys” on the service account page) is a different kind of key, and Obaket does not accept it yet. Keep the secret private: do not paste it into chats, issue trackers, or screenshots.

Step 5. Connect in Obaket

  1. In Obaket, click the + (Add Connection) button in the sidebar.
  2. Under “Choose a storage service to connect,” select Google Cloud Storage, then click Next.
  3. Check the Connection Name, and enter the Bucket name, the Access key, and the Secret. There are no endpoint or region fields; Obaket always connects to storage.googleapis.com.
  4. Click Test to check the connection, then click Save. The connection appears in the sidebar; select it to browse the bucket.

Your files stay between your Mac and Google Cloud. Obaket talks to Cloud Storage directly and has no server of its own. The secret is stored in the macOS Keychain on your Mac. See the Privacy Policy for details.

Things to know

Deleted files may still count toward your storage

New buckets keep deleted and replaced objects for 7 days (soft delete) unless you change the setting, and buckets with Object Versioning keep older versions. Google Cloud charges for this storage. Obaket does not remove these copies; change the bucket settings in the console if you do not want them.

Locked files cannot be deleted or replaced

If the bucket has a retention policy or an object has a hold, Google Cloud refuses to delete it until the retention period ends or the hold is removed. Obaket shows this as a permission error.

Organization policies can block HMAC keys

If your organization sets the policy constraints/storage.restrictAuthTypes to block HMAC keys, you cannot create keys, and existing keys stop working. Ask your Google Cloud administrator. See Organization policy constraints for Cloud Storage.

Very large moves

Moving or renaming a file larger than 5 GiB is done as one copy on Google’s side. Google Cloud stops a copy of more than 2.5 GiB that takes longer than 30 seconds, so large moves can fail. When a move fails, the original file stays where it was.

Change (rotate) the key

  1. Create a new HMAC key for the same service account (Step 4).
  2. In Obaket, right-click the connection in the sidebar, choose Edit, enter the new Access key and Secret, and click Save. Check that you can browse the bucket.
  3. In the console, on the Interoperability tab, click the service account under Access keys for service accounts, and change the old key to Inactive.
  4. Wait at least 3 minutes, then delete the old key. A key must be inactive before you can delete it, and a deleted key cannot be recovered.

A service account can have up to 10 HMAC keys.

Troubleshooting

Test fails with an access error

  • Check that you entered the HMAC key (the Access key starts with GOOG1), not values from a JSON key file.
  • Check that the key is Active on the Interoperability tab. A key you just created can take up to a minute to work.
  • Check that the service account has Storage Object User on this bucket (Step 3), and that the bucket name is spelled correctly.
  • If your organization blocks HMAC keys (see above), the key cannot be used.

Remove the connection

Right-click the connection in the sidebar and choose Delete. This removes the stored secret from your Mac. The HMAC key still works in Google Cloud; deactivate and delete it in the console if you no longer need it.
